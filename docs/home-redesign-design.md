## 1. 레퍼런스 분석 — 더카트 홈 구조 (실측 기준)

더카트 홈은 **"섹션 모듈의 수직 나열"** 구조다. 상단부터:

| # | 모듈 | 내용 |
|---|---|---|
| 1 | GNB | 로고 / TIME DEAL·BEST·SPECIAL 3개 메뉴 / 검색·마이·장바구니·로그인. 극단적 미니멀 |
| 2 | 히어로 배너 캐러셀 | 브랜드 기획전 배너 20장 로테이션 (01•20 인디케이터) |
| 3 | 액티비티 카테고리 그리드 | 골프/러닝/스윔/테니스 + 여성/남성 진입점 |
| 4 | 특가 상품 레일 | 할인율 강조 가로 스크롤 카드 |
| 5 | 브랜드 라인업 카드 | 기획전 배너 6장 그리드 |
| 6 | 브랜드 스포트라이트 | 브랜드 1개 대형 비주얼 + 해당 브랜드 상품 레일 15개 |
| 7 | 시즌 아이템 | 탭 칩(썬바이저/스커트/스윔웨어 등) 전환형 상품 그리드 |
| 8 | 랭킹 섹션 | "지금 인기있는 아이템" 1~20위 넘버링 + 카테고리 탭 |
| 9 | MD'S PICK | 탭 칩 전환형 상품 그리드 |
| 10 | 핫 브랜드 그리드 + 라인 배너 + 푸터 | 브랜드 진입 + 사업자 정보 |

### 디자인 언어 핵심 3가지

- **화이트 배경 + 상품 사진이 컬러를 담당** — UI는 무채색으로 물러나 있음
- **단일 패턴의 반복** — "탭 칩으로 필터되는 상품 레일/그리드" 하나가 섹션마다 반복
- **브랜드 우선 큐레이션 톤** — 섹션 제목이 전부 브랜드/테마 중심 (무신사 계열 커머스 정석)

## 2. kfashionly 설계안

### 2-1. 설계 전제 (중요)

더카트를 그대로 베끼면 안 되는 이유가 **데이터**에 있다.
더카트의 타임딜·쿠폰·랭킹은 자체 거래 데이터에서 나오지만, kfashionly는 구매대행으로
판매 데이터가 아직 없고, 상품은 **크롤링 → DRAFT → 승인 플로우**로 유입된다.

→ **레이아웃 패턴은 차용하되, 각 섹션의 데이터 소스를 우리 Prisma 스키마로 재정의한다.**

### 2-2. 섹션 매핑표

| 더카트 모듈 | kfashionly 버전 | 데이터 소스 |
|---|---|---|
| 히어로 캐러셀 | 브랜드 기획 배너 (관리자 등록) | 초기: 설정 배열 / 추후: Banner 모델 |
| 액티비티 그리드 | 카테고리 그리드 (아우터/상의/하의/신발/ACC + 여성/남성) | Category |
| 특가 레일 | 할인율 상위 상품 레일 | Product, (정가-판매가)/정가 내림차순 |
| 브랜드 스포트라이트 | 주간 피처 브랜드 1개 + 상품 15개 | Brand 지정 + 해당 브랜드 최신 상품 |
| 시즌 아이템 (탭 칩) | 탭 칩 상품 그리드 | Category/태그 필터 |
| 랭킹 1~20 | 초기: 신상품 랭킹(최신 등록순) → 추후 조회수/판매 기반 전환 | Product (status=ACTIVE) |
| 타임딜 | **초기 제외** — 구매대행은 원가가 원 사이트에 종속, 딜 가격 통제 불가 | — |
| 핫 브랜드 그리드 | 취급 브랜드 전체 그리드 (말본·지포어·타이틀리스트 등) | Brand |

> **랭킹을 "신상품 기준"으로 시작하는 이유**: 판매 데이터가 없는 상태에서 가짜 판매랭킹을
> 만들면 표시광고법(거짓·과장 표시) 이슈 소지가 있다. 초기엔 NEW 랭킹으로 정직하게 간다.

### 2-3. 디자인 시스템

| 항목 | 정의 |
|---|---|
| 컬러 | 화이트 베이스 + 블랙 텍스트. 무채색 기반, 할인율 표기만 red-500 계열 |
| 타이포 | Pretendard. 섹션 제목 국문 볼드 20~24px + 영문 서브라벨 병기 |
| 상품 이미지 비율 | 3:4 고정 |
| 반응형 | 모바일 퍼스트. 상품 그리드 모바일 2열 → md 3열 → lg 4~5열, 레일은 스와이프 |

### 2-4. 공통 컴포넌트 (4개 — 이것만 만들면 홈이 완성됨)

- **ProductCard** — 3:4 이미지 / 브랜드명(소형 볼드) / 상품명 2줄 말줄임 / 할인율%+판매가 / NEW·품절 배지 오버레이. 사이트 전체 단일 컴포넌트로 통일 (원자 단위)
- **SectionHeader** — 제목 + 영문 라벨 + 더보기 링크
- **ProductRail** — 가로 스크롤(스냅), 모바일 스와이프
- **TabbedProductGrid** — 칩 형태 탭 + 그리드, 탭 전환은 클라이언트 상태

### 2-5. 홈 섹션 최종 구성 (위→아래)

1. **GNB** — 로고 / NEW·BEST·BRAND / 검색·마이·장바구니. 스크롤 시 sticky
2. **히어로 캐러셀** — 3~5장, 자동 로테이션 + 번호 인디케이터(01•05 형식)
3. **카테고리 그리드**
4. **"놓칠 수 없는 특가"** — 할인율 상위 20개 ProductRail
5. **브랜드 스포트라이트** — 피처 브랜드는 설정값으로 교체 가능
6. **"지금 주목할 아이템"** — TabbedProductGrid, 최신 등록순 20개, 1~20 넘버링
7. **취급 브랜드 그리드**
8. **푸터** (사업자 정보 기존 값 유지)

### 2-6. 기술 제약

- 서버 컴포넌트 우선, 탭/캐러셀만 클라이언트 컴포넌트
- 이미지는 next/image + 자체 스토리지 URL만 (원 사이트 핫링크 절대 금지)
- 더카트의 이미지·문구·로고 복사 금지, **레이아웃 패턴만 참조**
- status=DRAFT 상품 홈 노출 금지 — 쿼리 레벨 보장 + 테스트 확인
- 기존 /admin 라우트는 건드리지 않음

## 3. 실무 포인트

- **홈 품질은 상품 이미지 품질이 결정한다.** 더카트가 좋아 보이는 건 레이아웃보다
  브랜드 화보급 이미지 덕이 크다. 크롤링 이미지 중 흰 배경 대표컷 위주로 승인하는
  **검수 기준을 잡는 것이 디자인 작업보다 효과가 클 수 있다.**
- **히어로 배너는 디자인 소스가 지속 필요하다.** 유니버랩 디자인 리소스로
  브랜드 기획전 배너 템플릿(피그마)을 만들어 돌려쓰는 것을 권장.
- **진행 방식**: 사전 확인 보고 → 공통 컴포넌트 4개 + 섹션 1~4 구현 후 미리보기 확인
  → 승인 후 섹션 5~8 완주. **커밋은 로컬만, 푸시 금지.**

### 4-2. 데이터 현실 (DB 실측)

- ACTIVE 상품 **277개** / 할인 상품 32개 / ACTIVE 보유 브랜드 **8개** (어뉴골프84·Alo Yoga60·Kolon30·Salomon24·TNF22·markandlona22·Arc'teryx20·Wilson15)

- `Brand.logoUrl` 12건 / 골프 하위 카테고리 상품: 액세서리40·슈즈23·상의16·아우터13·하의10 → **시즌 탭 데이터 충분**
