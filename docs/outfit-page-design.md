# 추천 코디(의상 조합) 페이지 설계안

> 작성: 2026-07-21 · 성격: 설계 (코드 무변경, 착수 전 승인 대기)
> 목표: "상의+하의+신발+악세" 조합을 제안하고 **한 번에 담게** 해서 객단가를 올리는 페이지

## 0. 설계 전제 — 데이터 실사 결과

| 사실 | 설계에 미치는 영향 |
|---|---|
| **어뉴골프**: 상의17·하의7·신발20·악세40 — 풀 코디 가능한 유일한 브랜드 | v1 코디는 어뉴골프 중심 + 크로스브랜드(markandlona 상하의 + Wilson/어뉴 신발) |
| markandlona 상의12·하의4·신발3, Arc'teryx 상의7·하의5 | 골프 외 아웃도어 코디 1~2개 가능 |
| 판매 데이터 0 | "인기 코디" 불가 → **에디터 큐레이션**으로 시작 (홈 랭킹과 같은 정직 노선) |
| **Lookbook 모델이 이미 90% 일치** (title/slug/cover/isPublished/상품 join/관리자 폼까지) | **새 테이블 만들지 않는다** — 룩북 모델 확장으로 감 |
| 상품마다 사이즈 옵션(variants) 존재 | "전체 담기"는 사이즈 선택 UX가 핵심 난제 → 아래 §4 |
| 폐쇄몰 게이트 | 신규 경로는 자동으로 로그인 필요(추가 작업 없음) |

## 1. 데이터 모델 — 신규 테이블 0개, additive 컬럼 2개 (사전승인 범위)

**Lookbook을 코디 겸용으로 확장**한다. 코디 = "아이템 3~5개짜리 초소형 룩북 + 역할 라벨"이므로 구조가 동일하다.

```prisma
model Lookbook {
  ...기존 그대로...
  kind  String?  // null=일반 룩북(기존), "OUTFIT"=추천 코디  ← additive nullable
}

model LookbookProduct {
  ...기존 그대로...
  role  String?  // "TOP" | "BOTTOM" | "SHOES" | "ACC" | "OUTER" — 코디 슬롯 라벨  ← additive nullable
}
```

- 기존 룩북 데이터·페이지에 영향 0 (kind=null 유지)
- 마이그레이션은 ADD COLUMN 2줄 — 사전승인된 additive nullable 범위
- 커버 이미지: Lookbook.coverImage가 required이므로, 관리자에서 커버 미입력 시
  **첫 상품 메인컷을 자동 저장** (스키마 변경 없이 해결). 상세 페이지 비주얼은
  커버 유무와 무관하게 **상품 콜라주(2×2)**를 기본 렌더로 사용 가능

## 2. 페이지 구조

### `/outfits` — 코디 목록
- 카드 그리드 (모바일 2열 → lg 3열). 카드 구성:
  - 비주얼: 커버 이미지 or **구성 상품 2×2 콜라주** (화보 없어도 성립하는 fallback — 브랜드 라인업 카드와 동일 패턴)
  - 제목 + 구성 요약 미니 썸네일 줄(3~5개 원형)
  - **"코디 총액" = 구성 상품 판매가 합** (할인가 기준) — 코디의 핵심 소구
- 탭 필터: 전체 / 골프 / 아웃도어 (kind=OUTFIT + gender/season 재사용 가능)

### `/outfits/[slug]` — 코디 상세 (핵심 화면)
```
┌─────────────────┬──────────────────────────┐
│                 │  코디 제목 + 설명(스타일링 노트)   │
│  비주얼 영역        │  ── 구성 아이템 (역할별) ──      │
│  (커버 화보 or     │  [TOP]    썸네일·상품명·가격·사이즈▾ │
│   상품 콜라주,      │  [BOTTOM] 썸네일·상품명·가격·사이즈▾ │
│   클릭 시 해당      │  [SHOES]  썸네일·상품명·가격·사이즈▾ │
│   상품으로 스크롤)   │  [ACC]    썸네일·상품명·가격       │
│                 │  ──────────────────────  │
│                 │  합계  ₩XXX,XXX (≈¥X,XXX)  │
│                 │  [전체 장바구니 담기]  [개별 담기] │
└─────────────────┴──────────────────────────┘
  하단: "이 코디의 브랜드" 링크 + 다른 코디 레일
```
- 각 아이템 행에서 **인라인 사이즈 선택** (기존 variants 데이터) — 상세 페이지 왕복 없이 완결
- 품절 아이템: 흐림 + "품절" 배지 + 합계에서 자동 제외(체크박스 해제 상태)
- 아이템 체크박스로 부분 선택 담기 (기본 전체 체크)

### 진입점 3곳
1. **GNB 서브탭**: `NAV_TABS`에 "코디"(/outfits) 추가 — 룩북 옆
2. **홈 섹션**: 기존 `SpringCollection`(시즌 코디 슬라이드, 현재 whatsNew 재탕 중)을 **코디 레일로 교체** — 홈에서 죽어 있던 섹션이 실데이터를 얻음
3. **상품 상세**: "이 상품이 포함된 코디" 레일 (LookbookProduct 역참조 — 쿼리 1개)

## 3. 큐레이션 운영 (판매 데이터 없이 시작하는 법)

| 단계 | 방식 | 근거 |
|---|---|---|
| **v1 (런칭)** | 관리자 수동 큐레이션 6~10개 — 기존 `/admin/lookbooks` 폼에 "코디" 체크 + 상품별 역할 셀렉트 추가 | 관리자 폼·액션 이미 존재, 추가 UI 최소 |
| v2 | 반자동 제안: 같은 브랜드 내 TOP 선택 → BOTTOM/SHOES 후보 자동 노출(관리자 보조 도구) | 어뉴골프처럼 풀카테고리 브랜드에 유효 |
| v3 (데이터 후) | 함께 구매된 조합 기반 자동 코디 | OrderItem 데이터 쌓인 뒤 |

**v1 큐레이션 소재 (실데이터 기준 바로 만들 수 있는 것):**
- 어뉴골프 남성 라운드룩 (상의+하의+신발+볼캡)
- 어뉴골프 여성 라운드룩
- markandlona 상하의 + 어뉴 신발 크로스 코디
- Arc'teryx 아웃도어 레이어링 (상의+하의)
- 어뉴골프 악세서리 스타터 세트 (장갑+볼캡+양말류)

## 4. "전체 담기" UX — 이 페이지의 성패 지점

- 의류는 사이즈 필수 → **담기 전 각 행에서 사이즈 선택을 끝내게 함** (미선택 시 해당 행 하이라이트 + 버튼 비활성)
- 사이즈 무관 상품(FREE/악세)은 셀렉트 자체를 숨김 (기존 `-FREE` SKU 자동생성 로직과 일치)
- 담기 = 기존 `addToCart` 서버액션을 아이템별 순차 호출 (신규 결제 로직 0)
- 성공 toast: "코디 4개 상품이 장바구니에 담겼습니다 → 장바구니 보기"
- (운영 옵션) "코디 완성 구매 시 5% 쿠폰" — 기존 Coupon 시스템으로 코드만 발급하면 됨, 개발 불필요

## 5. i18n / 폐쇄몰 / 정직성 원칙

- UI 라벨(역할명 TOP/BOTTOM…, 합계, 담기 버튼, 빈 상태)은 **Shop 네임스페이스 확장** — 3개 언어 동시 작업 (이번 i18n 표준 절차 그대로)
- 코디 제목/스타일링 노트는 운영 카피 → v1은 짧은 영문 제목 권장("Anew Weekend Round"), 다국어 카피 필드는 v2 검토
- "추천"의 근거 표기: **"에디터 추천"으로 명시** (인기순/판매순 표현 금지 — 홈 NEW 랭킹과 동일한 표시광고법 정직 노선)
- `/outfits`는 미들웨어 화이트리스트 밖 → 자동으로 회원 전용 (폐쇄몰 정책 일관)

## 6. 구현 순서 (승인 시)

1. 마이그레이션: `Lookbook.kind` + `LookbookProduct.role` (ADD COLUMN 2줄)
2. 쿼리: `getOutfits()` / `getOutfitBySlug()` / `getOutfitsContaining(productId)`
3. `/outfits` 목록 + `/outfits/[slug]` 상세 (콜라주 fallback + 인라인 사이즈 + 전체담기)
4. 관리자: lookbook-form에 "코디(OUTFIT)" 토글 + 상품행 역할 셀렉트
5. 진입점: NAV_TABS "코디" + 홈 SpringCollection → 코디 레일 교체 + 상품상세 역참조 레일
6. i18n 3개 언어 + E2E 검증(담기 플로우) → 빌드 → 배포

예상 규모: 신규 페이지 2 + 컴포넌트 2~3 + 관리자 폼 수정 1 + 쿼리 3. 스키마 리스크 없음(additive 2컬럼).

## 7. 하지 않기로 한 것 (명시)

- ❌ 새 Outfit 전용 테이블 — Lookbook 확장으로 충분, 모델 분열 방지
- ❌ AI 자동 코디 생성 — 상품 풀 277개·컬러/소재 메타 부재로 품질 보장 불가, v3에서 재검토
- ❌ "인기 코디" 정렬 — 판매 데이터 없음, 에디터 큐레이션 sortOrder로 대체
- ❌ 코디 전용 결제(세트 상품화) — 재고·환불 정합성 복잡도 대비 실익 없음, 장바구니 담기로 충분
